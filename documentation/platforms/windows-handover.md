## 1. What this project is

A native photo app (Apple Photos style: browse, view, edit, delete, albums,
search) that is a client of a Synology NAS (DS925+) over its Web API. The goal is
to move the owner, Sahil, off iCloud while keeping an independent backup.

- **macOS app: built and in daily use.** SwiftUI shell with an AppKit grid, over
  the shared Rust core.
- **Windows app: your job.** Same features, same safety rules, on the same core.
- **Synology only.** The app touches only the NAS: never iCloud, a phone, or a
  local photo library.

## 2. Safety invariants (non negotiable, same as macOS)

1. **Never destroy an original.** Edits are non destructive: an edited copy is
   uploaded as a new asset, and the original on the NAS is never modified.
2. **Delete is soft and confirmed.** Everyday delete goes to the DSM recycle bin
   and always asks first. Before every delete, read the recycle bin setting
   (`recycle_bin_status()` in the core). If it is Disabled, refuse to delete and
   tell the user where to turn it on. If it is Unknown, the confirm must say the
   delete may be permanent. Permanent delete exists only in the Recently Deleted
   view, behind its own confirm.
3. **Nothing reaches iCloud or the phone.**
4. **Destructive commands only ever reach a fake.** Tests that exercise delete,
   restore or empty use a fake core, never the real NAS. A test that falsifies a
   guard must not be able to reach a real side effect while the guard is off.

**The FFI boundary.** Everything the UI needs is a method on `PhotosCore` in
`core/photoscore/src/lib.rs`. The Mac app calls it through UniFFI generated Swift.
The Windows app must call the SAME methods. Do not reimplement API, sync or index
logic in the Windows UI. If the UI needs something new, add it to the core first,
with Rust tests, so both platforms get it.

## 4. Set up the Windows machine

1. Git for Windows, PowerShell 7, and Tailscale (the NAS is reached over Tailscale).
2. Add `.gitattributes` on day one if it is not there: `* text=auto` and
   `*.sh text eol=lf`, so shell scripts keep LF line endings.
3. Visual Studio 2022 Build Tools with the "Desktop development with C++"
   workload (MSVC linker and Windows SDK; `ring` and the bundled SQLite need them).
4. rustup. The repo pins the toolchain in `rust-toolchain.toml` (1.97.1 at
   handover). Add the Windows target if rustup does not do it:
   `rustup target add x86_64-pc-windows-msvc` (or `aarch64-pc-windows-msvc` on an
   ARM machine). Consider adding the Windows target to `rust-toolchain.toml`.
5. Run the core gate: `pwsh scripts/ci/ci.ps1 core`. It was written on the Mac
   and has NEVER been run on Windows. Expect to fix it first. Making it green is
   milestone 0.

Baseline at handover, on macOS: `cargo test --workspace` 364 passed, 0 failed,
1 ignored (the real NAS test). Swift unit tests 498 passed. The core has no known
Mac only dependency (TLS is rustls with ring, SQLite is bundled, secrets are
stored by the platform app, not the core), but it has never been compiled for
Windows. Any Windows specific failure in the core is a real bug: fix it in the
core, never with a Windows only fork.

## 5. The NAS (live testing)

- Host `fafnir.ladon-pirate.ts.net` (Tailscale MagicDNS, `100.87.107.5`), port
  `5001`, HTTPS with a self signed certificate (pin the leaf, or allow untrusted
  TLS for quick probes only).
- Photos are in Personal space (`SYNO.Foto.*`). Shared space (`FotoTeam`) returns
  error 801: not enabled.
- The DSM account has 2FA. Ask Sahil for the username and ONE fresh OTP, log in
  with `enable_device_token=yes`, and save `sid`, `synotoken` and the device token
  to a session scoped temp file (never in the repo). Afterwards, re login with the
  device token instead of an OTP. An OTP expires in about 30 seconds: have the
  login command ready BEFORE asking for the code. Never write a password into any
  file. Remind Sahil to rotate it if it appears in chat.
- API facts verified on this NAS:
  - State reads (browse, thumbnail, download) need the `X-SYNO-TOKEN` header, or
    DSM returns error 119.
  - Thumbnails and downloads key on `unit_id` (from `additional.thumbnail.unit_id`),
    NOT the item id. `SYNO.Foto.Thumbnail` max version is 2.
  - The browse list needs `additional=["thumbnail","resolution"]`.
  - Delete (`SYNO.Foto.Browse.Item delete`, v7) moves the file to
    `/home/#recycle/Photos/<same relative path>` within a second.
  - Restore is `SYNO.FileStation.CopyMove` with `overwrite=false` and
    `remove_src=true`, done in under a second. **The restored photo gets a NEW
    Photos id**, so album, favorite and tag links are probably lost (open TODO).
  - File Station error 408 means the file or folder does not exist.
  - `SYNO.Core.User.Home get` returns `enable_recycle_bin` (an admin only API).
- Prefer reproducing NAS issues through the core's real path (login, probe
  capabilities, crawl, fetch, thumbnail) in a throwaway
  `core/photoscore/examples/*.rs`. Delete it afterwards and never commit it.

## 6. The first decision: Windows UI technology

This decision is Sahil's. Ask once, give the recommendation, and per the working
rules do not idle waiting: build milestone 0 (core green on Windows) meanwhile.

| Option | For | Against |
|---|---|---|
| **WinUI 3 (C#) + `uniffi-bindgen-cs`** (recommended) | Native Windows look and feel, which matches the Mac's "native UI over a shared core" design. Virtualized grids (`ItemsRepeater`) handle 100k items. Best match for an Apple Photos class app. | A second UI language. `uniffi-bindgen-cs` is third party (NordSecurity): pin its version to the repo's UniFFI version. |
| Rust native UI (Slint, egui) | One language, no binding layer. | Less native feel, a weaker grid and image pipeline, more custom work for Photos style polish. |
| Tauri (web UI over Rust) | Fast UI iteration. | Web rendering for a huge thumbnail grid, and not native. |

## 7. Milestones for Windows

0. Core builds and tests green on Windows via `scripts/ci/ci.ps1 core`. Add a
   `.gitattributes`. Fix any Windows breakage in the core.
1. Skeleton app under `platforms/windows/` with the bindings generated into the
   app (tracked, like the Mac's generated Swift), plus `ci.ps1 windows`, a build
   script under `scripts/windows/`, and a smoke test.
2. Login with an OTP, the device token, and the session stored in Windows
   Credential Manager (the Keychain equivalent; never in plain files or settings).
3. Read only browse: crawl into the local index, a virtualized grid from the local
   index (never block on the network), the thumbnail cache, and a detail view.
4. Delete parity with every safety rule in section 2, plus Recently Deleted
   (restore and permanent delete), with confirm and gate tests against a fake core.
5. Then search, people, places, map and edit, following the Mac app.
   `documentation/plans/done/` and `Fixed.md` say how each was built.

## 8. Working rules (repeated from the Mac global rules)

- Commit straight to `main`. No feature branches, no worktrees. Commit and push
  after every logical chunk.
- Commit messages read like a human developer. **No AI attribution of any kind:**
  no Co-Authored-By lines, no "Generated with" footers, no mention of Claude or AI
  in commits, code comments or docs. This overrides any harness reminder.
- No dashes as punctuation in prose (no em dash, en dash, or " - " used as a
  dash). Use full stops, commas or colons.
- Parallel workers: each owns its own paths (record them in `tasks.md`), commits
  with pathspecs (`git add <paths> && git commit -m "msg" -- <paths>`), never
  `git add -A`, and never two workers holding edits in the same file. At most 2
  Opus and 4 Sonnet workers at once. Watch CPU on the machine.
- **Falsify every test:** revert the fix, watch the test fail, restore it, watch it
  pass, and report that you did. A test you have not seen fail proves nothing.
- Verify by running, not by reading. Report real counts (passed, failed, skipped)
  and real exit codes.
- `TODO.md` holds only pending work, newest section at the top, with a
  `Last Updated` line. Finished work moves to `Fixed.md` with commit hashes. Any
  deferral gets a TODO item in the same turn. Keep `tasks.md` current while
  workers run.
- Plans go in `documentation/plans/YYYY-MM-DD-name.md`, and move to
  `documentation/plans/done/` with `> **Status:** DONE` when finished.
- Prefer the repo's scripts over ad hoc commands. If a script is missing, write
  one. If a script fails, fix the script.
- Before shipping anything touching delete, edit, sync or auth, run an adversarial
  review (skeptic sub agents).
